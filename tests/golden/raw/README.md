# Raw metadata-contract fixtures

What the frontend (`SchemaService` and friends) and the MCP server (`schema-cache.ts`) read from PostgREST at bootstrap, captured from the live stack of every example instance, once per role. Later golden-output generators read these files without a database.

Layout: `<example>/<role>[.<locale>]/<endpoint>.json`, plus `<example>/meta.json` and `MANIFEST.json`. Roles: `anon` (no Authorization header), `testuser`, `testeditor`, `testmanager`, `testadmin` (each preceded by `rpc/refresh_current_user`). `pothole` additionally has `<role>.es/` (sends `Accept-Language: es` and captures `rpc.get_translations_for_locale` for `es`; the app never fetches translations for `en`). Non-200 responses are stored as `{ "__status": N, "__body": ... }`.

Endpoint fixtures use the dotted name of the call: `schema_entities` (frontend query, no order), `schema_entities.mcp` (MCP query with its `order=`), `rpc.get_statuses_for_entity.<entity_type>` (once per distinct status/category entity type visible to that role), and so on. `meta.json` lists every endpoint with its path and consumer, the HTTP status per role and endpoint, sort keys, masked fields, and redactions. `ROLE_VARIANCE.md` (generated by `scripts/golden/role-variance.mjs`) documents what differs by role.

## Regenerating (explicit, never on test runs)

```bash
# one example, one stack at a time (postgres + postgrest + keycloak only), isolated compose project sdk-<example>
scripts/golden/capture-all.sh pothole
scripts/golden/capture-all.sh                 # all 8 examples
scripts/golden/capture-all.sh --alt           # same, on the ALT Docker slot (+30000 host ports, project sdk-alt-<example>)
scripts/golden/capture-all.sh --check         # fresh boot + capture, diff against the committed fixtures (non-zero on any diff)
node scripts/golden/role-variance.mjs         # refresh ROLE_VARIANCE.md after a recapture
```

`capture-raw.mjs` alone assumes a stack is already up (`POSTGRES_URL`-style overrides: `POSTGREST_URL`, `KEYCLOAK_TOKEN_URL`; defaults are the standard ports):
`node scripts/golden/capture-raw.mjs --example pothole [--example ...] | --all [--check]`.

Set `DOCKER_HEAVY_LOCK` (or `DOCKER_ALT_LOCK` with `--alt`) to a mutex directory to serialize heavy Docker use; the lock is released between examples. Output is byte-identical on either slot.

First-time init of an example takes several minutes under amd64 emulation; the script boots postgres alone and polls it because compose's own dependency wait gives up too early.

## Determinism rules

Verified by capturing every example twice and re-booting fresh stacks (pothole three times, across both Docker slots, neighborhood-hub twice; `--check` over all 8 examples must report zero diff).

- Keys are sorted recursively, 2-space indent, trailing newline.
- Arrays are sorted by the keys recorded in `meta.json` (`sortedBy`): the consumer's explicit `order=` columns, or the natural key where the consumer sends none, with NULLs last and the row's JSON as final tie-break. Ties on `sort_order` and unordered views changed row order between boots, so server order is not preserved.
- Masked (`__MASKED__`): `created_at` / `updated_at` on every row, and `version` in `schema_cache_versions` (boot-time timestamps; the frontend only compares versions for equality with its cache). Nothing the interpretation logic reads is masked.
- Redacted: personal data in `static_text` (the mottpark example embeds a named individual's payment handle, phone and email, see `meta.json` `redactions`). Surrounding text is kept.
- Not captured because it is volatile or irrelevant to the contract: HTTP headers, records of entity tables, timing.

## Provenance

`meta.json` records `git rev-parse HEAD:examples/<example>` and `HEAD:postgres/migrations` at capture time. `--check` prints a WARN when either tree hash has moved since the fixtures were taken (a hint that a recapture may be due) but only fails on content differences. `capturedAt` is excluded from comparisons.

To keep the stack small only `postgres`, `postgrest` and `keycloak` are started; the worker, MinIO, Inbucket, Swagger and MCP containers play no part in the metadata contract. A missing `examples/<ex>/.env` is created with `POSTGRES_DB`/`POSTGRES_PASSWORD` only (the file is gitignored; `.env.example` is not copied because several contain unquoted `SMTP_FROM` lines that compose cannot parse).
